# Сборка и обычный запуск Fate RPG

Готовая сборка уже создана. Для игры дважды нажмите **Fate RPG.exe** в корне проекта. Откроется окно управления сервисами и браузер по адресу `http://localhost:3008`.

Это production-режим: Fast Refresh и автоматическая пересборка отсутствуют. После изменения исходников нужно заново выполнить сборку.

## Пересборка

Запустите `build.bat` или выполните:

```powershell
npm.cmd run build
```

Для сборки нужен установленный Node.js 22 и зависимости корневого приложения и обоих mini-services. Шрифты включены локально; обращаться к Google Fonts при сборке не требуется. Сборка не выполняет миграции и не создаёт новую игровую базу.

В результате создаются `.next/standalone`, готовые JavaScript-сервисы, встроенный runtime Node.js и `Fate RPG.exe`. На Windows exe компилируется штатным C#-компилятором .NET Framework 4.x. Для обычного запуска собранной версии Bun и системный Node.js не нужны.

## Способы запуска

- **Fate RPG.exe** — рекомендуемый запуск, окно управления и автоматическое открытие браузера.
- **start.bat** — запускает тот же exe; если его нет, пробует встроенный Node.js.
- **npm.cmd start** — запускает тот же production-набор сервисов из терминала; завершение Ctrl+C.
- **npm.cmd run dev** — только для разработки, с Fast Refresh.

Исходный установочный start.bat сохранён под именем `start-legacy.bat`; для обычной игры он больше не нужен.

Exe — окно запуска, а не архив всех данных в одном файле. Не переносите только exe: оставьте рядом папку `.next`, `db/custom.db` и настройки `.env`. Пользовательская база остаётся в `db/custom.db` исходной папки; встроенный сервер получает абсолютный DATABASE_URL. Для резервных копий также используется исходная папка, а не временные файлы сборки.

## Завершение работы

Откройте **«Ещё» → «Выход»** на локальной странице мастера и подтвердите остановку. Приложение завершит туннель и сервисы, браузер покажет «Приложение остановлено». После этого вкладку можно закрыть.

Также можно закрыть окно **Fate RPG.exe**. Windows Job Object привязывает к нему всё дерево процессов: Next.js, signaling, физику и localtunnel. Даже принудительное завершение exe не должно оставлять эти процессы работающими.

Закрытие обычной вкладки браузера само по себе сервисы не останавливает: вкладку можно случайно закрыть или обновить во время игры. Для остановки используйте кнопку или окно управления. Кнопка «Выход» скрыта у сетевых игроков; сервер разрешает управление только локальному origin с одноразовым токеном текущего запуска. Публичный туннель не получает эту возможность.

Если один из обязательных сервисов аварийно завершается, supervisor останавливает остальные. Второй экземпляр не запускается поверх занятых портов и не завершает чужие процессы. Сообщения запуска и ошибки записываются в `logs/runtime.log`.

## Игра через интернет

Откройте «Сеть», создайте комнату и публичную ссылку localtunnel. Туннель ведёт на **3008** и обслуживает приложение, signaling и физику по одному адресу. Доступность провайдера localtunnel остаётся внешним условием; production-сборка не исправляет его сетевые ограничения.

## Проверки

Проверены production build, запуск из exe со встроенным Node без обращения к корневым npm-зависимостям, чтение существующей базы, HTTP/Socket.IO шлюза, запрет удалённой остановки, кнопка «Выход» в Chrome и освобождение портов 3000/3004/3006/3008. При принудительном завершении exe также проверено закрытие реального процесса localtunnel с локальным тестовым провайдером. Публичный интернет-туннель из ограниченной среды агента не проверен.

Текущая настройка Next `ignoreBuildErrors: true` сохранена: в исходном проекте остаются 30 диагностик TypeScript. Успешная production-сборка не означает, что они исправлены.
