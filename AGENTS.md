# Работа с проектом

Перед изменениями прочитать [context.md](context.md): там описаны назначение, структура, потоки данных и ограничения текущей portable-поставки. Контекст основан на статическом анализе от 2026-10-17; сверять его с актуальным кодом.

- Сохранять пользовательские данные в db/custom.db и настройки .env. Анализ и документирование не требуют запуска start.bat, миграций или восстановления базы.
- Основная активная сеть находится в src/hooks/use-network.ts; src/lib/p2p содержит отдельную реализацию. Перед изменением проследить фактические импорты.
- Не монтировать одновременно desktop/mobile варианты карты и сцен кубиков: это приводит к повторному запуску бросков.
- Для новых бросков использовать src/lib/roll-executor.ts; учитывать дедупликацию событий, физические сессии, журнал и удалённых участников.
- При изменении данных согласовывать типы, Prisma, сериализацию JSON, API, store и импорт/экспорт. Учитывать старые сохранения.
- Проверять доступность команд: в исходной поставке отсутствует scripts/, хотя на неё ссылается package.json. Сборка настроена игнорировать ошибки TypeScript.
- После существенных изменений актуализировать context.md. В отчёте указывать проведённые проверки и то, что не проверялось.
- Путь localtunnel описан в LOCAL_NETWORK.md: туннель направляется на Node gateway 3008, а не на Next 3000. Удалённые signaling и physics должны использовать origin страницы. Проверять вход свежего игрока без сохранённого приключения.
- Production собирается npm run build; запуск через Fate RPG.exe, start.bat или npm start. Инструкции в PRODUCTION.md. После правки исходников пересобрать bundle; не проверять изменённые исходники на устаревшей standalone-сборке. Контроллер остановки gateway доступен только локальному владельцу; не расширять его на публичный origin.
