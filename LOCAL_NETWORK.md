# Игра через localtunnel

Для обычной игры используйте **Fate RPG.exe** или `start.bat`: собранная production-версия запускает все сервисы без Fast Refresh. Сборка и завершение работы описаны в [PRODUCTION.md](PRODUCTION.md). Команда `npm run dev` ниже предназначена для разработки.

Запустите из корня проекта:

```powershell
npm.cmd run dev
```

Команда запускает приложение (3000), signaling (3004), физику (3006) и Node.js-шлюз (3008). Нужен Bun: launcher использует локальный `.tools/node_modules/bun/bin/bun.exe`, если он установлен, иначе ищет `bun` в PATH. Зависимости обоих mini-services должны быть установлены.

1. Откройте `http://localhost:3008`, выберите приключение и сцену.
2. Откройте «Сеть», укажите имя и создайте комнату мастера.
3. В выборе адреса нажмите «Создать ссылку для интернета» в блоке localtunnel.
4. Передайте игроку ссылку с `?join=КОД`, которую показывает приложение.
5. Игрок открывает её, вводит имя и подключается. Данные приключения загружаются автоматически; создавать своё приключение не нужно.

После перезагрузки вкладка автоматически возвращается в прежнюю комнату с той же ролью. У мастера восстанавливается действующая ссылка туннеля. Сохранение относится к текущей вкладке; кнопка «Покинуть сессию» удаляет его. После обновления серверного кода перезапустите приложение и signaling, чтобы применить исправления переподключения.

Публичный сервис localtunnel может показать промежуточную страницу доступа и запросить tunnel password. Её нужно пройти в браузере игрока; это страница провайдера, а не пароль комнаты Fate. Поведение и доступность публичного сервиса зависят от провайдера.

При запуске через существующий `start.bat` кнопка туннеля сама поднимет шлюз 3008. При остановке такого туннеля остановится и созданный им шлюз. Если шлюз уже запущен через `npm run dev`, кнопка остановит только туннель.

## Запуск туннеля из терминала

При работающем `npm run dev` во втором терминале:

```powershell
npm.cmd run tunnel
```

Команда выведет JSON с публичным URL. Добавьте к нему `/?join=КОД_КОМНАТЫ`. Остановка — Ctrl+C. Вместо этой команды можно вызвать установленный пакет напрямую:

```powershell
.\node_modules\.bin\lt.cmd --port 3008 --local-host 127.0.0.1
```

Туннелировать нужно **3008**, а не 3000: через 3000 доступна только страница/API, без маршрутизации Socket.IO. Caddy и cloudflared для этого пути не требуются.

Для собственного сервера localtunnel перед запуском приложения/туннеля можно задать `LOCALTUNNEL_HOST` (URL сервера); необязательный `LOCALTUNNEL_SUBDOMAIN` задаёт запрашиваемое имя. Публичный адрес не гарантируется постоянным.

## Архитектура

```text
Браузер игрока → HTTPS/WSS localtunnel → Node gateway :3008
                                          ├─ обычные URL → Next.js :3000
                                          ├─ XTransformPort=3004 → signaling
                                          └─ XTransformPort=3006 → physics
Браузер ведущего ↔ WebRTC DataChannel ↔ браузер игрока
```

Шлюз поддерживает HTTP, POST-тела, Socket.IO polling и WebSocket upgrade. Разрешены только два известных значения XTransformPort. Оба удалённых Socket.IO-клиента используют origin открытой страницы, без обращений к localhost устройства игрока. Существующая топология WebRTC со STUN/TURN сохранена: localtunnel публикует веб-сервисы, но не заменяет ICE/TURN для канала между браузерами.

API `/api/tunnel/start`, `/status`, `/stop` управляет отдельным процессом npm-пакета localtunnel. Состояние общее для API-маршрутов, повторный start не создаёт второй туннель. Таймаут запуска — 30 секунд; stop и ошибки закрывают принадлежащие контроллеру процессы. Скачивание cloudflared удалено.

## Проверки

```powershell
npm.cmd run test:gateway
npm.cmd run test:signaling
.\.tools\node_modules\.bin\bun.cmd test scripts/tunnel-lifecycle.test.ts
.\.tools\node_modules\.bin\bun.cmd test scripts/network-session.test.ts
```

Первый тест проверяет HTTP и Socket.IO через шлюз. Второй использует настоящий пакет localtunnel и локальный тестовый сервер провайдера: проверяет TCP-передачу, start/status/stop, повторный start и отмену запуска. Он не зависит от доступности публичного localtunnel.

Дополнительно проверен вход свежего игрока в Chrome через локально перенаправленный домен player.loca.lt: реальный signaling, загрузка сцены из тестовых API-ответов и два WebSocket через общий origin. Проверка публичного localtunnel в текущем окружении завершилась таймаутом без получения URL; подключение через интернет с другого устройства пока не подтверждено.

Production standalone-сборка теперь включает Node.js, скомпилированные mini-services, `scripts/gateway.cjs`, `scripts/tunnel.cjs` и необходимые npm-зависимости. `npm start` поднимает весь набор, а не только Next.js.

Документация пакетов: [localtunnel](https://github.com/localtunnel/localtunnel), [node-http-proxy](https://github.com/http-party/node-http-proxy).
